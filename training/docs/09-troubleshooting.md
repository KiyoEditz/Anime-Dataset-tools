# 09 — Panduan Troubleshooting & Penanganan Kendala

Dokumen ini adalah matriks diagnosis cepat untuk mengenali gejala error, akar penyebab, serta tindakan perbaikan selama proses persiapan dataset, training di Molab, dan ekspor model.

---

## Matriks Diagnosis Cepat

| Gejala / Pesan Error | Akar Penyebab | Tindakan Solusi Cepat | Rujukan Teknis |
|---|---|---|---|
| **`ENV GATE: tidak bisa lanjut` (`tier: blocked`)** | Kapasitas disk bebas di `/root/work` kurang dari 90 GB, atau VRAM GPU < 24 GB. | Minta instance disk yang lebih besar di Molab (minimal 150 GB), atau alihkan ke model fallback 12B. Periksa apakah `/tmp` yang sempit memicu false alarm. | [docs/fix/05 § M2](fix/05-env-gate-dan-library.md#m2--gate-disk-ikut-menghitung-tmp) |
| **`CUDA out of memory (OOM)` saat forward/backward pass** | `gradient_checkpointing` tidak aktif, batch size terlalu besar, atau LoRA melatih seluruh model (*full fine-tune*). | Pastikan `gradient_checkpointing=True`, turunkan `per_device_train_batch_size` ke `2`, dan verifikasi bahwa adapter LoRA terpasang dengan benar (trainable $\le 3\%$). | [docs/fix/01 § C8](fix/01-notebook-marimo.md#c8--trainer-dibangun-tanpa-lora)<br>[docs/fix/02 § M15](fix/02-metode-lora-bf16-dan-vision.md#m15--anggaran-vram-bf16-31b) |
| **Loss bernilai `NaN` atau error `Attempting to unscale FP16 gradients`** | Model Gemma berjalan pada presisi `fp16` alih-alih `bfloat16`. | Pastikan GPU mendukung bf16 dan set `bf16=True`, `fp16=False` pada `TrainingArguments`. Jangan pernah melatih Gemma pada float16 murni. | [docs/fix/02 § C5](fix/02-metode-lora-bf16-dan-vision.md#c5--fallback-diam-diam-ke-fp16) |
| **Model terus berbicara tanpa henti (*runaway generation*)** | Token penutup giliran (`<end_of_turn>` / EOS) terpotong saat pemotongan sekuens (*truncation*) di collator. | Jangan buang token penutup saat truncating, atau buang baris yang melebihi batas sekuens agar model selalu belajar memprediksi token EOS. | [docs/fix/04 § H2](fix/04-chat-template-dan-masking.md#h2--truncation-memotong-token-end-of-turn) |
| **Model mengulangi pertanyaan user (*echoing*)** | Loss dihitung pada seluruh teks percakapan (system & user tidak ter-masking dengan `-100`). | Periksa hasil *chat template proof*. Pastikan seluruh token prompt sebelum giliran model diberi label `-100`. | [docs/fix/04 § H3](fix/04-chat-template-dan-masking.md#h3--asumsi-messages2-dan-multi-turn) |
| **`This cell redefines variables from other cells` (Marimo Error)** | Variabel global atau import library diulang di beberapa cell (misal `shutil`, `torch`). | Gunakan alias lokal berawalan garis bawah (misal `import shutil as _shutil` atau `from ... import snapshot_download as _snapshot_download`). | [docs/fix/01 § C1](fix/01-notebook-marimo.md#c1--global-marimo-didefinisikan-di-lebih-dari-satu-cell) |
| **`FileNotFoundError: training/gguf_convert.py`** | Path skrip ekspor GGUF berupa path relatif yang tidak ada di direktori kerja container Molab. | Pastikan skrip `gguf_convert.py` diunduh bersamaan saat tahap bootstrap di Cell 2. | [docs/fix/06 § H5](fix/06-merge-gguf-evaluasi.md#h5--cell-gguf-tidak-bisa-jalan-di-molab-dan-membuang-vision) |
| **Kapasitas disk habis saat proses merge / GGUF** | Cache Hugging Face lama belum dibersihkan atau kalkulasi preflight mengasumsikan file bf16 berukuran 0,5x. | Hapus folder cache model dasar setelah bobot tersimpan di VRAM. Jangan aktifkan quant `Q8_0` jika sisa disk < 120 GB. | [docs/fix/06 § H6](fix/06-merge-gguf-evaluasi.md#h6--merge-klaim-disk-salah-dan-cache-yang-dihapus-keliru)<br>[docs/fix/06 § M4](fix/06-merge-gguf-evaluasi.md#m4--rumus-preflight-gguf-salah-untuk-bf16) |
| **Kemampuan gambar rusak (*vision broken*) setelah training** | Adapter LoRA menyuntikkan gradien ke modul encoder visual (Vision Tower) atau `mmproj` tidak diekspor ke GGUF. | Bekukan seluruh layer vision dengan `requires_grad=False`, batasi target modul LoRA hanya pada language layers, dan sertakan flag `--mmproj` saat konversi GGUF. | [docs/fix/02 § C4](fix/02-metode-lora-bf16-dan-vision.md#c4--target-lora-bisa-mengenai-vision-tower)<br>[docs/fix/06 § H5](fix/06-merge-gguf-evaluasi.md#h5--cell-gguf-tidak-bisa-jalan-di-molab-dan-membuang-vision) |
| **Resume selalu mulai dari langkah 0 (*scratch*)** | Strategi penyimpanan checkpoint Hugging Face mengunggah ke `last-checkpoint/`, namun kode mencari `checkpoint-*`. | Samakan pola direktori penyimpanan checkpoint di `TrainingArguments` dengan fungsi pencarian snapshot download. | [docs/fix/01 § C6](fix/01-notebook-marimo.md#c6--resume-dari-hub-tidak-pernah-menemukan-checkpoint) |
| **`GatedRepoError` / `RepositoryNotFoundError`** | Akses ke repositori model Hugging Face belum terbuka atau token tidak memiliki izin baca. | Buka halaman model `KiyoEditz/Gemma-4-Dark-Gemistry-31B` di browser, pastikan akses sudah terbuka pada akun Anda, lalu gunakan Hugging Face Token Anda. | [docs/fix/05 § M5](fix/05-env-gate-dan-library.md#m5--id-model-fallback-dan-ambang-tier) |
| **`No usable pairs found` saat `prepare_dataset.py`** | Folder `output/` belum diekstrak di mesin lokal atau path sumber pada `sources.json` keliru. | Jalankan pipeline ekstraksi dialog dari novel atau pastikan file `output/raw_dialogue_pairs.jsonl` telah diletakkan di workspace. | [docs/fix/03 § M9](fix/03-dataset-dan-split.md#m9--folder-output-tidak-ada) |
