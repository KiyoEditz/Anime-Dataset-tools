# Hasil Verifikasi Asumsi Gemma 4 (Fase 0: V1–V6)

Tanggal verifikasi: 2026-11-07  
Target Model Eksklusif: **`KiyoEditz/Gemma-4-Dark-Gemistry-31B`** (Roleplay Specialist, LoRA bfloat16 penuh pada NVIDIA Blackwell 96 GB, tanpa fallback ke model generic).

---

## Ringkasan Hasil V1–V6

| ID | Aspek Verifikasi | Hasil Temuan Faktual | Dampak pada Perbaikan Kode |
|---|---|---|---|
| **V1** | Panjang token baris terpanjang (`train.jsonl`) | Dari 3.528 baris train, 346 baris (10%) memakai long system prompt (`8.791` karakter; total baris maks `9.878` karakter). Pada tokenizer Gemma 4 (`vocab_size=262144`), prompt 8.791 karakter sendiri menghasilkan ~2.150–2.450 token (> `MAX_SEQ=2048`), menyisakan budget negatif dan membuat 346 baris gagal tokenisasi. | **C2, M15:** Naikkan `CFG["MAX_SEQ"]` dari `2048` ke `4096` untuk mode full, dan tambahkan proteksi di `tokenize_with_mask()` / `_encode()` agar baris yang melampaui batas ditangani dengan aman tanpa memotong token penutup `<turn|>`. |
| **V2** | Hierarki nama modul Language Model vs Vision Tower | Berdasarkan `config.json` dan `model.safetensors.index.json` pada `KiyoEditz/Gemma-4-Dark-Gemistry-31B` (`Gemma4ForConditionalGeneration`, 1.189 tensor):<br/>• **Language Model (410 modul linear):** `model.language_model.layers.{i}.self_attn.{q,k,v,o}_proj` dan `model.language_model.layers.{i}.mlp.{gate,up,down}_proj`<br/>• **Vision Tower & Projector (355 modul):** `model.embed_vision.embedding_projection`, `model.vision_tower.patch_embedder`, serta `model.vision_tower.encoder.layers.{i}.{self_attn,mlp}.{q,k,v,o,gate,up,down}_proj.linear`. | **C4:** Karena vision encoder juga memiliki submodul bernama `q_proj`, `k_proj`, dll., gunakan regex ketat `r"^(?!.*(?:vision|visual|audio|embed_vision)).*(?:language_model|text_model|model)\.layers\.\d+\.(?:self_attn|mlp)\.(?:q|k|v|o|gate|up|down)_proj$"` (cocok tepat 410 modul bahasa dan 0 modul vision), bekukan eksplisit seluruh parameter vision/projector/audio (`requires_grad = False`), dan assert `0` parameter LoRA aktif di komponen visual. |
| **V3** | Chat template (`processor` vs `tokenizer`), prefix-stability, dan blok thinking | Berdasarkan `chat_template.jinja` (17.708 byte) dan `tokenizer_config.json` pada `KiyoEditz/Gemma-4-Dark-Gemistry-31B`:<br/>1. Token kontrol Gemma 4 menggunakan `<|turn>system\n`, `<|turn>user\n`, `<|turn>model\n` (`sot_token="<|turn>"`) dan penutup `<turn|>\n` (`eot_token="<turn|>"`), **bukan** `<start_of_turn>` / `<end_of_turn>`.<br/>2. Role `system` didukung secara native (`<|turn>system\n...<turn|>\n`).<br/>3. Saat `add_generation_prompt=True` (default `enable_thinking=False`), template menyuntikkan blok pemikiran kosong `<|turn>model\n<|channel>thought\n<channel|>`. Namun saat `add_generation_prompt=False` (render penuh), giliran asisten tanpa field `reasoning` dirender sebagai `<|turn>model\n{content}<turn|>\n` (tanpa `<|channel>thought\n<channel|>`). | **H7, H3, H2:** Salin `chat_template` dari processor bila `tokenizer.chat_template` kosong. Perbarui `derive_turn_parts()` dan `tokenize_with_mask()` di `elaina_train_lib.py` agar menangani perbedaan blok `<|channel>thought\n<channel|>` antara `add_generation_prompt=True` dan `False`, menyertakan `<|turn>model\n<|channel>thought\n<channel|>` sebagai bagian prompt yang di-mask (`-100`) agar 100% identik dengan inferensi, serta mendukung percakapan multi-turn dan single-turn tanpa kehilangan token `<turn|>`. |
| **V4** | ID Model Target & Smoke Test | • `KiyoEditz/Gemma-4-Dark-Gemistry-31B` terverifikasi aktif di Hugging Face Hub (`Gemma4ForConditionalGeneration`, 13 shard safetensors + `model-lmhead.safetensors`).<br/>• `google/gemma-4-E2B-it` terverifikasi aktif dengan arsitektur `Gemma4ForConditionalGeneration` yang sama untuk smoke test.<br/>• Sesuai instruksi, **tidak ada fallback** ke `google/gemma-4-31B-it` atau `12B`. | **M5, H4:** Set `MODEL_ID` utama secara eksklusif ke `KiyoEditz/Gemma-4-Dark-Gemistry-31B` tanpa fallback model generic, dan gunakan `google/gemma-4-E2B-it` untuk `ELAINA_MODE=smoke`. |
| **V5** | Kewajiban `token_type_ids` / `mm_token_type_ids` pada `forward()` | Inspeksi `transformers/models/gemma4/modeling_gemma4.py` (`Gemma4ForConditionalGeneration.forward`) membuktikan parameter multimodal bernama `mm_token_type_ids: torch.LongTensor \| None = None` dan bersifat **opsional** (`None`) untuk input teks murni. | **H10:** `ResponseOnlyCollator` aman untuk batch teks murni (`input_ids`, `attention_mask`, `labels`), dan ditambahkan dukungan meneruskan/mem-padding `token_type_ids` serta `mm_token_type_ids` (dengan `0`) bila tersedia pada fitur input. |
| **V6** | Kernel PyTorch `sm_120` (Blackwell) & versi `transformers` | GPU Blackwell `(12, 0)` membutuhkan PyTorch `>= 2.7.0` dengan CUDA `>= 12.8` (`cu128`) yang memuat `sm_120` di `torch.cuda.get_arch_list()`, serta `transformers >= 5.5.0.dev0` (atau git main) untuk `model_type: "gemma4"`. | **H8, M1:** Perbaiki cell install agar memasang wheel `cu128` jika `sm_120` belum ada, memasang `transformers` yang mendukung `gemma4`, mencegah `unsloth` menimpa `torch`, serta memperbaiki fungsi `check_torch_cuda_compat()` di `elaina_train_lib.py`. |
